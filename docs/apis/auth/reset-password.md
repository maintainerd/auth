# Reset Password

Set a new password using the signed reset link delivered by the forgot-password flow. The URL signature (`sig` + `expires` + `token`) is validated before the password is accepted. Available on both ports.

**Base URL (Internal — Port 8080):** `http://localhost:8080`
**Base URL (Public — Port 8081):** `https://auth.example.com`

---

## Endpoints

| Method | Path | Auth | Port | Description |
|--------|------|------|------|-------------|
| POST | /api/v1/reset-password | None | 8080 | Reset password using a signed token (client_id optional in URL) |
| POST | /api/v1/reset-password | None | 8081 | Reset password using a signed token (client_id required in URL) |

---

## POST /api/v1/reset-password

Consume a password reset token and set a new password. The token and all associated parameters (`client_id`, `provider_id`, `expires`, `sig`) are embedded in the signed URL sent to the user by email — they are not supplied independently.

The signed URL is validated for integrity and expiry before any password change is attempted. The token is then rate-limited and consumed.

### Authentication

None required.

### Differences Between Ports

| | Port 8080 (Internal) | Port 8081 (Public) |
|-|----------------------|--------------------|
| `client_id` / `provider_id` | Extracted from signed URL if present (optional) | Extracted from signed URL (required) |

### Query Parameters (from signed URL)

These parameters are embedded in the reset link generated by the server. Do not construct them manually.

| Parameter | Description |
|-----------|-------------|
| token | Reset token |
| client_id | Client ID (required on port 8081, optional on port 8080) |
| provider_id | Provider ID (required on port 8081, optional on port 8080) |
| expires | URL expiry timestamp |
| sig | HMAC signature |

### Request Body

Content-Type: `application/json`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| new_password | string | Yes | New password to set |

### Response

#### 200 OK

```json
{
  "success": true,
  "message": "Password reset successful",
  "data": {
    "message": "Password reset successful",
    "success": true
  }
}
```

#### Error Responses

| Status | Message | Description |
|--------|---------|-------------|
| 400 | Invalid request body | Malformed JSON |
| 400 | Validation error | `new_password` missing or invalid |
| 400 | Invalid signed URL | URL signature invalid or parameters tampered |
| 400 | Missing required parameters in signed URL | `token`, `client_id`, or `provider_id` absent (port 8081) |
| 400 | Reset failed | Token already used or expired |
| 429 | Too many requests. Please try again later. | Rate limit exceeded |

```json
{
  "success": false,
  "message": "Invalid signed URL"
}
```

### Examples

The reset link from the email looks like:

```
https://auth.example.com/api/v1/reset-password
  ?token=reset-token-value
  &client_id=my-app
  &provider_id=default
  &expires=1716100000
  &sig=hmac-signature
```

POST the new password to that URL:

**Internal (port 8080):**

```bash
curl -X POST "http://localhost:8080/api/v1/reset-password?token=reset-token-value&expires=1716100000&sig=hmac-signature" \
  -H "Content-Type: application/json" \
  -d '{
    "new_password": "NewSecure@Pass1"
  }'
```

**Public (port 8081):**

```bash
curl -X POST "https://auth.example.com/api/v1/reset-password?token=reset-token-value&client_id=my-app&provider_id=default&expires=1716100000&sig=hmac-signature" \
  -H "Content-Type: application/json" \
  -d '{
    "new_password": "NewSecure@Pass1"
  }'
```
